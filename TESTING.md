# Building and testing

## Prerequisites

- Windows 10 version 2004 (build 19041) or newer, or Windows 11.
- .NET 10 SDK (the Windows Desktop targeting packs are included). Internet access is needed when NuGet packages are first restored.

`build.ps1` runs `dotnet restore` and `dotnet build`; it no longer downloads `nuget.exe`, .NET Framework reference assemblies or Windows Runtime metadata. Run from PowerShell:

```powershell
.\build.ps1 -Configuration Release      # bin\Release
.\build.ps1 -Configuration Portable     # bin\Portable; data in AppData beside the binaries
.\test.ps1                              # builds Debug and runs every test
.\test.ps1 --filter 'FullyQualifiedName~MouseCaptureTests'
$env:GESTURESIGN_UPDATE_GOLDEN = "1"; .\test.ps1   # rewrite golden files only intentionally
```

The solution also defines `Centennial` and `uiAccessRelease`. The latter selects the UIAccess daemon manifest but still requires signing and a secure installation location for Windows to grant UIAccess. Tests and the input recorder build in `Debug` and `Release`. The recorder output is in `GestureSign.InputRecorder/bin/<Configuration>`; the test assembly is in `GestureSign.Tests/bin/<Configuration>`.

## Test suite

`GestureSign.Tests` uses xUnit 2.9.3 and `dotnet test` on .NET 10. It covers the input pipeline from raw HID digitizer reports to recognized gestures, plus the typed named-pipe command/payload boundary.

| Layer | Tests | Input |
|---|---|---|
| HID preparsed data | `Hid/PreparsedDataBuilderCorpusTests` | 25 real Windows dumps from hidapi (`Fixtures/hidapi`) |
| HID encode/decode | `Hid/HidDescriptorRoundTripTests` | Synthetic touchpad, touch screen and pen descriptors; real `hid.dll` |
| WM_INPUT decoding | `Input/RawInputProcessorTests` | Synthetic reports: screen mapping, hybrid frames, ROOT devices, pen-suppresses-touch window, device arbitration |
| Event translation and capture state machine | `Input/MouseCaptureTests`, `Input/TouchAndPenCaptureTests` | Mouse hook messages, decoded touch/pen frames |
| Gesture matching | `Gestures/GestureMatchingTests` | `GestureSign.ControlPanel/Defaults/Gestures.gest` |
| Continuous-gesture upgrade | `Gestures/ContinuousGestureCatalogTests`, `Gestures/LegacyMigrationSerializationTests` | Locked catalog writes, retry, export/reload preservation and name-only successful migration |
| End-to-end golden replay | `Replay/GoldenReplayTests` | `Fixtures/Replay/**/*.gsrec.json` |
| Recorder buffer conversion | `Recording/RawInputConverterTests` | Fabricated RAWINPUT buffers |
| Recorder contact decoding | `Recording/ContactTrackerTests` | Synthetic touchpad, touch screen and pen reports; synthetic recordings |
| Local IPC | `InterProcessCommunication/NamedPipeProtocolTests` | Typed gesture/device messages and rejected malformed frames over real named pipes |

## How the pipeline is made testable

The daemon's input path is split so it runs without windows, hooks or hardware:

- `RawInputProcessor` decodes WM_INPUT buffers. `MessageWindow` only registers devices and forwards buffers. It depends on `IRawInputDeviceSource` (RIDI_* queries) and `IRawInputEnvironment` (tick count, screen under the cursor, orientation).
- `PointEventTranslator` takes `IInputSettings` and a callback for the strokes captured so far, instead of `AppConfig` and `PointCapture.Instance`.
- `PointCapture` has an internal constructor taking `IInputSettings` and `ICaptureHost`. The host covers process priority, click reinjection, cursor position, training IPC, the recognized gesture name and UI-context timers. The production constructor adds the overlay, `InputProvider`, the WinEvent hook and the UIAccess filter on top.

## Golden replay corpus

A `*.gsrec.json` recording (schema: `GestureSign.InputRecorder/Recording/InputRecording.cs`) holds:

- device names and usages;
- base64 preparsed data;
- raw HID payloads per WM_INPUT;
- mouse hook events;
- monitor layout, orientation and input settings.

`InputReplayer` feeds a recording through the real pipeline and writes a transcript to the sibling `*.expected.json`, one JSON object per observable step:

- `raw`: decoded frames;
- `translated`: down/move/up with `handled` and capture state;
- `capture`: started/completed with strokes and recognized gesture;
- `hook` and `host`: mouse hook decisions and side effects such as click reinjection.

Both files are language-neutral, so a port (for example Rust) can replay the same corpus and diff transcripts.

- `Fixtures/Replay/synthetic/` is generated by `Replay/SyntheticRecordings.cs` in update mode. It covers touchpad (1–3 fingers, second monitor), touch screen (single, tap, 3-finger hybrid in one or split WM_INPUTs, 90/180/270° rotation, ROOT device), pen (barrel+tip, hover, eraser, touch suppression) and mouse (drag, click, initial timeout).
- `Fixtures/Replay/recorded/<device>/` holds real hardware recordings made with `GestureSign.InputRecorder` (see its README). Per-machine instance IDs in device names are replaced with `SCRUBBED`.

A failing golden test prints the first differing line and writes the full `*.actual.json` next to the test binary.

## .NET 10 migration smoke checks

The desktop UI, overlay and feedback delivery require runtime checks in addition to the suite above. Use copied/isolated user data rather than modifying a user's live configuration.

- Open the control panel with non-default drawing settings (for example Middle mouse button, 17-pixel trail, 2300-ms initial timeout and eraser/hover pen input). Initialization and restoring settings must preserve those values; explicit user changes must still save.
- Select an all-enabled application, then one with mixed enabled/disabled commands. Selection must not change either flag. Exercise individual and bulk switches, including bulk changes while filtering and clearing the filter; switches must remain visible at the default window size.
- Open New/Edit Application and ignored-application dialogs; render checked and unchecked radio buttons in plugin settings without resource exceptions.
- Import icons into existing iconless normal and ignored applications through both archive and downloaded-settings import. Navigation rows must refresh without restarting.
- Draw a one-finger trail, then begin a hidden two-finger capture. The preceding overlay must disappear.
- In the recorder, release after a take while idle digitizer reports continue. Auto-stop/auto-save must occur after the original lift delay. Renewed contacts/buttons must cancel that delay, and the next release must start a fresh one. Replaced contact IDs in a split hybrid frame must not inflate the maximum simultaneous count.
- Hold `ContinuousGestures.gsc` readable but unwritable while loading legacy actions. The original actions must remain intact, including exported/backed-up motion. Release the lock and retry: the catalog must be durable before named action references are saved, and the daemon must receive the application reload notification.
- Exercise feedback against a local HTTP endpoint using the internal `Feedback.Send(string, Uri, TimeSpan)` overload. Check multi-chunk success, rejection partway through a report, HTTP 429, redirects, offline connection and timeout. Do not send test logs to the production endpoint; only acknowledged delivery may produce the success UI.
- Exercise the touch-keyboard fallback from a non-elevated installation and the recorder's touchpad Settings link. Shell-based launch must work under .NET 10.


## Not covered

- `PointerInputTargetWindow` (UIAccess touch interception and injection). It needs a signed build installed in a secure location, plus a touch screen.
- Overlay drawing (`SurfaceForm`), tray, triggers (`HotKeyManager`, `MouseTrigger`, `ContinuousGestureTrigger`), plugins, and the ControlPanel UI. Check these by hand on the relevant hardware.
